# Аналитика квартир

Статический сайт на GitHub Pages: аналитика квартир Брусники в Тюмени по выгрузкам с сайта застройщика. Сборки нет — ES-модули в `js/` и два файла данных в `data/`.

## Что на странице

- **Сводка и «Проекты»** — по последней выгрузке.
- **«Изменения»** — сравнение двух выгрузок: изменили цену, новые, исчезли. Даты выбираются в самом блоке; по умолчанию выбранная выгрузка сравнивается с выгрузкой недельной давности (код — `compareChoice` в `js/dataset.js`).
- **«Квартиры»** — таблица или шахматка дома. Клик открывает панель квартиры: цены, карусель (планировка, план с размерами, план этажа с подсвеченной квартирой, вид из окон), график цены, события.

Фильтры, вкладки и открытая квартира хранятся в адресе страницы — ссылкой можно поделиться. Параметры — в `js/url-state.js`.

## Данные

- **`data/history.json`** — все выгрузки. Постоянные поля квартиры записаны один раз, цена и площадь — точками изменения, наличие в выгрузках — интервалами. Формат описан в `scripts/history.py`; сайт разворачивает файл обратно в строки выгрузок (`js/history.js`).
- **`data/flats.json`** — постоянные данные квартир: позиция на этаже, картинки, статус застройщика, вид из окон, бронь на дату сбора и готовая раскладка шахматки. Здесь же квартиры, проданные до первой выгрузки.

Оба файла пишут скрипты из `scripts/`.

## Обновить данные

Каждый день это делает GitHub Action [`.github/workflows/collect.yml`](.github/workflows/collect.yml): в 09:17 по Тюмени запускает `python3 scripts/collect_flats.py` и коммитит `data/` сообщением «upd data ГГГГ-ММ-ДД». Расписание GitHub работает «по возможности» и иногда пропускает запуск, поэтому есть запасные запуски в 12:17 и 15:17: если выгрузка за сегодня уже есть, они сразу выходят, не обращаясь к серверу застройщика. Скрипт записывает список квартир в продаже как выгрузку дня (повторный запуск в тот же день её заменяет) и дозапрашивает в `flats.json` новое и изменившееся. Упавший запуск значит, что сервер застройщика не ответил: собранное закоммичено, остальное доберёт следующий запуск, GitHub пришлёт письмо. Запустить вне расписания: Actions → «Сбор данных» → Run workflow.

Вручную — из корня репозитория, начиная с `git pull`, потому что данные в репозитории обновляет Action:

1. `python3 scripts/collect_flats.py`. Готово, когда скрипт завершился без ошибки, а в `git diff data/history.json` есть сегодняшняя дата.
2. Закоммитить и запушить `data/` сразу, чтобы не разойтись с ежедневным коммитом Action.

### Перебор пропусков — локально, по ночам

Action собирает только свежее. Квартиры, проданные до начала выгрузок, ищет полный перебор ID всех домов — его запускают локально частями по 6000 ID (≈2,5 ч):

1. Вечером: `git pull`, затем
   `caffeinate -i python3 scripts/collect_flats.py --discover --discover-sweep --discover-limit 6000 --delay 1.5 --no-snapshot --cache-dir .cache`.
   Готово, когда скрипт завершился без ошибки; строка «Перебор: осталось проверить ID …» показывает остаток.
2. Утром, в любое время: Action мог закоммитить `data/flats.json` раньше, поэтому ночной результат накладывается на свежий файл повтором из кэша, без сети и конфликтов:
   ```
   git checkout -- data/
   git pull
   python3 scripts/collect_flats.py --discover --discover-sweep --offline --no-snapshot --cache-dir .cache
   ```
   Затем закоммитить и запушить `data/`.

Остальные режимы — `python3 scripts/collect_flats.py --help`. Старую CSV-выгрузку можно добавить вручную: `python3 scripts/history.py add файл.csv` (дата из имени файла или `--date ГГГГ-ММ-ДД`).

## Нагрузка на сайт застройщика

Сервер застройщика однажды закрыл соединения после ~4400 запросов за несколько часов. Поэтому:

- запросы идут последовательно с паузой `--delay` (по умолчанию 0,35 с; для больших проходов — 1,5 с);
- после 5 неудачных запросов подряд скрипт сам переходит на кэш, сохраняет собранное и завершается с ошибкой;
- поиск квартир (`--discover`) — это тысячи запросов: большие проходы дробятся по домам (`--discover-building`), а полный перебор ID всех домов (`--discover-sweep`) — по запускам через `--discover-limit N`. Проверенные ID запоминаются в `flats.json` сериями (`checked`), поэтому следующий запуск продолжает с непроверенных;
- `--cache-dir .cache` (папка в `.gitignore`) сохраняет сырые ответы: повторный прогон берёт их с диска, а `--offline` пересобирает файлы вообще без сети. Карточки квартир из выгрузки запрашиваются заново всегда — их статус меняется. Поиск по ссылкам читает именно этот кэш.

## Правила, которые неочевидны из кода

- **Статусов три.** «Продаётся» — квартира есть в последней выгрузке. «Забронирована» — есть в выгрузке и в брони, если бронь собрана не раньше последней выгрузки. «Продана» — в последней выгрузке её нет. Застройщик ставит «Продана» уже на время сделки, и при сорванной сделке квартира возвращается в продажу — отсюда «?» у статуса в панели. Код — `flatStatus` в `js/flats-data.js`.
- **Пустая «цена со скидкой» в выгрузке значит «скидки нет»**: цена покупки равна полной.
- **Шахматка складывается из SVG планов этажей застройщика**: группа `d{N}` в плане — позиция `number_on_floor` из карточки квартиры. Правила раскладки (пустые этажи, этажи выше заявленной этажности, две квартиры на одной позиции) — в описании `scripts/collect_flats.py`.
- **Двухуровневая квартира записана на этаж первого уровня и занимает этаж выше.** Признак — метка карточки «Двухуровневая» или «Второй свет» (`lv: 2` в `flats.json`). В шахматке у неё клетка в два этажа, а этаж выше сдвигается; на верхнем этаже секции второй уровень на кровле, и клетка обычная. Раскладка — `js/chess-model.js`.
- **Квартиры, проданные до первой выгрузки, находятся поиском по ID**: застройщик заводит квартиры дома пачками близких ID, и проданные прячутся в пропусках и у краёв этих пачек. Квартиры далеко от пачек находятся по ссылкам из ответов застройщика (соседи по этажу, та же планировка на других этажах, тот же вид из окон; ссылки читаются из кэша `--cache-dir`) и ночным перебором всех ID от наименьшего до наибольшего ID каждого дома. Истории цен у таких квартир нет; цена — полная из карточки застройщика.

## Запуск и проверка

- Локально: `python3 -m http.server` из корня и http://localhost:8000 (модулям нужен сервер, с `file://` страница не загрузится).
- Тесты: http://localhost:8000/tests/ — проходят, когда страница пишет «OK: N тестов».

## Устройство

- `index.html`, `style.css`, `flats.css` — страница.
- `js/` — модули: точка входа `main.js`, блок «Квартиры» — `flats-block.js` и соседние, данные — `history.js` и `flats-data.js`.
- `scripts/` — сбор данных, Python 3 только со стандартной библиотекой.
- `tests/` — браузерные тесты чистой логики.

Внешних зависимостей нет. Во время работы сайт берёт с `cdn.brusnika.ru` только картинки; планы этажей он загружает как SVG, чтобы подсветить квартиру.
